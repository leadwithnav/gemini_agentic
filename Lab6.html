Step 1: ADK Callback Architecture & Security Governance

Understand how before_tool_callback and after_tool_callback enforce governance and latency metrics in Google ADK V2.

🛡️ Security Interceptor Pipeline
Callbacks act as middleware interceptors executed before and after every tool invocation:
  • before_tool_callback: Validates Pydantic inputs, checks user permissions (e.g. alice vs guest), and enforces business guardrails (SELECT only, no mutation operations, authorized tables, project & dataset matching).
  • after_tool_callback: Records tool latency, logs structured observability metrics, and sanitizes sensitive response fields.
📂 Directory Architecture

├── callbacks/

├── integrations/
│   ├── incident_api/              # FastAPI incident REST backend
│   └── incident_mcp/              # FastMCP incident server

    └── mcp_tools.py               # MCP tools

Step 2: Agent Workflow Definition (app/agent.py)

Review the root workflow graph linking specialist sub-agents with before_tool_callback and after_tool_callback.

Python • app/agent.py 
from google.adk import Agent, Workflow, Event, Context
from ..tools.mcp_tools import incident_mcp_toolset
from ..tools.bigquery_tools import MODEL, PROJECT_ID, DATASET_ID, bigquery_toolset
from ..callbacks.callback_tools import before_tool_callback, after_tool_callback

# Specialist Agent with Callbacks Attached
market_status_support_agent = Agent(
    name="market_status_support_agent",
    model=MODEL,
    instruction="...",
    tools=[bigquery_toolset],
    before_tool_callback=before_tool_callback,
    after_tool_callback=after_tool_callback,
)

# Root Routing Workflow
root_agent = Workflow(
    name="lab6_callback_support_routing",
    edges=[
        ("START", save_original_request, request_classifier, route_request),
        (route_request, {
            "INCIDENT_SUPPORT": incident_support_agent,
            "MARKET_STATUS_SUPPORT": market_status_support_agent,
            "PRODUCT_SUPPORT": product_support_agent,
        }),
    ],
)
