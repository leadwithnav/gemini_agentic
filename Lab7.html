Step 1: ADK Runner, Sessions & Long-Term Memory Bank Architecture

Learn how Google ADK V2 manages short-term conversational session state alongside cloud-native long-term user memory banks.

⚡ Concept: Sessions vs Long-Term Memory Bank
  • Short-Term Session State (SessionService): Maintains active turn context (e.g. current_request, current_symbol, route) for a single conversation session.
  • Long-Term Memory Bank (VertexAiMemoryBankService): Persists user profile preferences, trading history, and historical facts across multiple independent sessions using Vertex AI Agent Engine.

Step 4: Part 3 — Vertex AI Memory Bank (Long-Term Memory)

Persist and query long-term user facts across sessions using VertexAiMemoryBankService.

🧠 Long-Term Memory Bank Persistence
VertexAiMemoryBankService allows the agent to recall user preferences (e.g. "Trader Alice prefers NQ futures") even in completely new sessions.
Python • app/part3_vertex_memorybank/runner.py 
from google.adk.memory.vertex_ai_memory_bank_service import VertexAiMemoryBankService

# Initialize Vertex AI Memory Bank Service
memory_service = VertexAiMemoryBankService(
    project=PROJECT_ID,
    location=LOCATION,
    agent_engine_id=AGENT_ENGINE_ID,
)

# Attach both Session Service and Memory Service to Runner
runner = Runner(
    agent=root_agent,
    app_name=APP_NAME,
    session_service=session_service,
    memory_service=memory_service,
)

# Query Long-Term Memories
memories = await memory_service.search_memory(
    app_name=APP_NAME,
    user_id=USER_ID,
    query="preferred trading product"
)
