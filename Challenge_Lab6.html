Lab 6 Challenge: Security Governance & Observability Callbacks

Implement enterprise security guardrails, Pydantic input validation, and execution latency logging using Google ADK V2 tool callbacks.

🎯 Challenge Objective
In this student challenge, you will implement before_tool_callback and after_tool_callback functions to govern and monitor tool executions across a hybrid CME Exchange Support Agent.

Learning Focus:
  • Before Tool Callback: Record start time, validate inputs with Pydantic, enforce SELECT-only SQL query policies, and restrict queries to the EXCHANGE_PRODUCTS table.
  • After Tool Callback: Read start time from workflow state, compute latency in milliseconds, log structured metrics, and store observability state.
  • Agent Wiring: Import and register both callbacks across your specialist agents.

Callback Interceptor Flow

             User Request
                  │
                  ▼
          Request Classifier & Router
                  │
                  ▼
         Specialist Support Agent
                  │
                  ▼
       ┌────────────────────────┐
       │  before_tool_callback  │ ◄── 1. Record Start Time
       └──────────┬─────────────┘ ◄── 2. Pydantic Input Validation
                  │               ◄── 3. Enforce SELECT-only & Table Guardrails
                  ▼
         [ Tool Execution ] (MCP / BigQuery)
                  │
                  ▼
       ┌────────────────────────┐
       │  after_tool_callback   │ ◄── 1. Read Start Time & Calculate Duration (ms)
       └──────────┬─────────────┘ ◄── 2. Log Structured Execution Metrics
                  │               ◄── 3. Update Observability State
                  ▼
            Final Response
💡 Middleware Interceptor Pattern
Tool callbacks act as lightweight middleware interceptors. Returning a dictionary with status: "BLOCKED" from before_tool_callback immediately halts tool execution and returns a structured error to the agent, protecting enterprise databases from unauthorized or malicious SQL statements!

Key Architectural Takeaways

📌 Governance & Observability Summary
1. Deterministic Security Interceptors: System prompts are advisory, but code callbacks provide strict, deterministic security boundaries. Callbacks run in pure Python before tool execution occurs, making them un-bypassable by prompt injection.

2. Enterprise Observability: By combining before_tool_callback (start timestamping) and after_tool_callback (latency computation & state recording), enterprise agent systems gain full visibility into tool performance and reliability metrics.
